# 区域商品目录采集服务

面向采购比价的本地数据采集与归档服务。服务从仓库自带的合成来源页读取各地区商品报价，规整为带「地区、包装规格、价格有效期」的记录并归档，再按指定时刻输出各地区报价的比较视图。全程不访问外部系统，便于在无网络环境下复现采集过程。

## 数据模型

`data/` 目录下每个 `.json` 文件是一个地区站点在某个时刻的页面快照：

- `region`：页面所属地区。同一型号同一规格按地区分别归档，互不影响。
- `observedAt`：页面采集时刻（ISO 时间）。
- `items[]`：目录条目，必填 `id`、`label`、`model`、`spec`、`price`。
  - `spec`：包装规格（如 `500g`、`1kg`），规整后作为独立比较维度；同一型号的不同规格分组比较，互不混淆。
  - `price.amount` / `price.currency`：价格与三字母币种代码。
  - `price.kind`：`regular`（长期价）或 `promo`（促销价）。
  - `price.validFrom` / `price.validUntil`：价格有效期；可只写 `YYYY-MM-DD`（截止日按当天结束计）。

有效期语义：

- 常规价未填有效期时，自采集时刻起长期有效，直到被更新的记录取代。
- 促销价必须填写 `validUntil` 才会成为当前价候选；缺截止日期的促销按「有效期未知」处理，有效窗口收敛到采集时刻，不会成为当前价，也不参与最优价。

## 迟到页面与过期促销

归档是追加式的：每条记录进入 `(型号, 规格, 地区)` 键下的历史，任何页面都不会覆盖已有记录。比较时按查询时刻的有效期窗口挑选各键的当前价，因此：

- 站点缓存里已结束的促销（`validUntil` 已过）不会显示为当前价；
- 迟到的旧页面即使最后到达，也顶不掉同地区更新的报价，更碰不到其他地区的报价；
- 没有有效报价的地区会展示最近一次记录及其状态（`expired` / `unknown` / `upcoming` / `inactive`），而不是把旧价当成现价。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs                # 以当前时刻比较
node src/pipeline.mjs 2026-12-01     # 以指定时刻比较（查看促销结束后的视图）
```

输出按 `(型号, 规格)` 分组：每个地区一条报价（含价格类型与有效期），`bestByCurrency` 给出各币种下当前有效报价中的最低价。测试使用项目内的合成记录，执行不需要网络、凭据或外部服务。
